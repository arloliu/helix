# v1.8.0 Phase 4 — Authorities, per-cluster replay, auto-recovery

Working plan for the Phase 4 items in
[`roadmap.md`](roadmap.md#phase-4--authorities-per-cluster-replay-auto-recovery-v180).
The roadmap table and the Design Decisions section are binding;
this file only fixes the order, the mechanism, and the verification for each item.
Finding IDs stay in the roadmap;
nothing below is quoted into code or commits.

## Scope and process

- Branch `feat/authorities` from `main` (`v1.7.0`, `8d7bdfb`).
  One commit per roadmap item, in the order below;
  two items share a commit only when they touch the same lines.
- Phase 5 (observability) is a second branch and PR after this one merges;
  `v1.8.0` is tagged after both.
- Every item: unskip or write the regression test first, then make it pass.
  Before each commit: `go fix ./...`, `make lint`, `make test-unit`, `/simplify`.
  Run `go test ./test/integration/` before every push that changes behaviour.
- `CHANGELOG.md` `[Unreleased]` gains one entry per observable change,
  with the one-line restore for every default that moves.
- External review (Codex, root-client and policy/replay reviewers in parallel) before the PR is opened,
  looping until both report nothing.

## Items

### 4.1 Per-cluster memory queues

`MemoryReplayer` keeps two channels per cluster (high and low) instead of two shared ones.
`Enqueue` routes by `TargetCluster` and priority;
the per-cluster slot accounting already present (`pendingA`, `pendingB`) stays the capacity authority.
`tryDequeueWithPriority` gains a cluster argument;
the worker's dequeue loop alternates clusters so one cluster's backlog cannot starve the other.
`Len`, `HighLen`, `LowLen`, `PendingByCluster`, and `DrainAll` keep their meaning.
Not observable from the public API except through fairness;
no CHANGELOG entry beyond a note.

Verification: existing replay tests unchanged;
a new test enqueues a backlog for A and confirms B payloads are dequeued while A's remain.

### 4.2 Observation hub

An unexported `clusterHealth` in root owns both `clusterStats` values and is the only writer of them.
It exposes one typed entry point per observation source instead of one flat method,
because the caller of each source still holds the live context and the routing state that classification needs:

| Entry point | Caller | Authority order (unchanged from today) |
|---|---|---|
| `readSucceeded(cluster, role, overrideActive, latency)` | `recordReadSuccess`, fallback success | primary role: `ReadStrategy.OnSuccess` unless override; `LatencyRecorder.RecordLatency` if implemented, else `FailoverPolicy.RecordSuccess`; then stats. Fallback role: stats only. |
| `readFailed(cluster, role, kind)` | `recordReadFailure`, fallback failure | `IncReadError`; stats when `kind` is a cluster error; `FailoverPolicy.RecordFailure`. `ReadStrategy.OnFailure` stays in the failover flow (routing, not observation). |
| `iterClosed(cluster, kind, overrideActive)` | `cqlIter.closeAndReport` | stats unless caller-context; then strategy and policy exactly as today (`RecordSuccess`, never `RecordLatency`). |
| `writeLeg(cluster, kind)` | `recordWriteOutcomeAt` (normal and strict) | stats only; a leg classified as caller-cancelled records nothing. |
| `deferredWriteLeg(cluster, kind)` | the `OnComplete` callback in `replayLeg` | stats only, bounded atomic updates, no user code, before `deferred.done()`. |
| `probe(cluster, err)` | `recoveryProbeLoop` | stats only (4.3 makes auto-refresh read them). |

`kind` is the already classified outcome (`readErrKind` or `writeLegErrKind`), so context provenance is decided where the context is live.
Deliberately outside the hub: immediate query CAS (reports no health today), source-side mirror execution (its payloads name a logical sink, not a root cluster), and `ReadStrategy.OnFailure`.
The hub adds no lock; `clusterStats` stays atomic.
No exported API changes.

Verification: a sequencing spy pins the exact authority calls for every source and role
(override-active success, latency success, primary failure, fallback failure, iterator results, strict write, deferred failure, probe failure);
caller-cancelled read and write cases prove no health authority is called;
a deferred completion racing `Close` commits its observation once and shutdown completes.
The read matrix test and the write regression tests are unchanged.

### 4.3 Auto-refresh consumes hub observations

- Seed `lastSuccessNanos` at construction and on every session swap.
- Deferred-write failures and recovery-probe failures reach the auto-refresh counters through the hub
  (source deferred write and probe).
- `WithAutoRefreshFailureClassifier(func(error) bool)`;
  the default counts `types.ErrClusterUnreachable` and Helix-owned leg or probe timeouts.
  Restore the old behaviour with `WithAutoRefreshFailureClassifier(func(error) bool { return true })`.
- `RefreshSession` closes the replaced session after a grace period (default one refresh timeout)
  instead of immediately, so in-flight operations on the old holder finish.

Category 1 for the first two bullets (documented "ALL of" contract);
CHANGELOG behaviour change for the classifier default.

Verification: unskip `TestAutoRefresh_DegradedClusterFailuresStillTriggerRefresh`
and `TestAutoRefresh_DoesNotReplaceHealthySessionOnSchemaErrors`;
the existing auto-refresh tests move their simulated errors onto the typed sentinel.

### 4.4 `ForceDegrade` sticky latch

`clusterWriteState` gains a `latched` flag set by `ForceDegrade`, cleared only by `ForceRecover` and `Reset`.
`recordFast` and `RecordProbeSuccess` never clear `isDegraded` while latched.
`recoveryProbeLoop` skips a latched cluster through a new optional interface (`IsLatched`),
so custom strategies are unaffected.
`docs/auto-recovery.md` documents the latch and drops the advice to disable the probe.
Category 1;
CHANGELOG behaviour change with no restore (no dependent identified).

Verification: unskip `TestRecoveryProbe_DoesNotClearForceDegrade`.

### 4.5 Probe hysteresis

- The probe credits recovery only when its own latency is within the strategy's `absoluteMax`
  (or the sibling's last latency plus the delta threshold).
  `RecordProbeSuccess` gains a sibling `RecordProbeLatency(cluster, d)` on a new optional interface;
  the old method is kept.
- `WithAdaptiveMinDegradedDwell(d)`: no recovery before `d` has elapsed since the degrade.
- Re-degrade backoff: each degrade within a window doubles the dwell, capped;
  a new `EventWriteFlapping` fires when the cap is reached.

Defaults keep today's behaviour (zero dwell, no backoff), so the dwell and backoff are additive.
The latency criterion is Category 1 because the documented probe contract is "the cluster responded quickly".

Verification: a policy test with a fast probe and slow writes stays degraded;
a flapping test counts transitions and the event.

### 4.11 `WithClusterWriteTimeout`

Root wraps each leg context in `writeLegs` with the configured timeout.
Expiry is a Helix-owned timeout:
`classifyWriteLeg` already treats a leg error with a live parent as a cluster error,
so the leg is replayed and counted as a health signal without new classification code.
Default zero (disabled).

Verification: a write test with one hanging session returns after the timeout,
acknowledges the fast leg, and enqueues replay for the slow one.

### 4.6 Route veto

Optional interface in root: `RouteVeto { VetoRoute(cluster ClusterID) bool }`.
Only `resolveReadTargetNormal` consults it, and only for a read that is not pinned, not preserving a legacy paging token, and not under an `AllowedClusters` override.
Drain and veto form one eligibility decision:
a cluster is eligible when it is neither draining nor vetoed;
an ineligible selection moves to the alternative only when the alternative is eligible;
when neither is eligible the strategy's selection stands (fail-closed to today's behaviour).
The veto never calls `OnFailure` and never changes a strategy's preference.
Pinned and preserved page-state reads, override reads, CAS, and single-cluster mode are untouched.
A `FallbackRead` probe treats a vetoed alternative like a draining one: it returns not-found without asking.

`LatencyCircuitBreaker` implements it from an atomic open-state snapshot written inside its existing trip and close transitions (no new lock, no call into `ShouldFailover`);
the snapshot stays open until the policy probe of 4.7 closes the breaker.
Category 3: off by default;
`WithRouteVeto(true)` enables it;
a startup `Warn` when the failover policy implements the interface and the option is off.
`docs/cluster-events.md` corrects the `circuit_breaker_open` action text.

Verification: unskip `TestRead_OpenLatencyBreakerReroutesReads` with the option enabled;
table cases for encoded and legacy page states, override, CAS, both vetoed, both draining, veto-plus-drain conflicts, a vetoed fallback alternative, and single-cluster mode;
every rerouted read asserts no `OnFailure` call and an unchanged sticky preference.

### 4.7 Breaker below threshold and policy probe

- `WithFailoverBelowThreshold(bool)` on both `NewCircuitBreaker` and `NewLatencyCircuitBreaker` (default `false`, Category 3).
  `ShouldFailover` stays side-effect free and answers "retry this request on the other cluster":
  unknown cluster → false; open or half-open → true; closed and below threshold → the option value.
  A `true` result follows today's path, including `ReadStrategy.OnFailure`, so with the option on a sticky preference may move on the first failure; the option's Godoc says so.
  Both breakers implement a read-only `FailoverBelowThreshold() bool` capability so root can emit the once-per-client startup `Warn` when a built-in breaker leaves it off.
- Half-open recovery moves to root and the timed close leaves `RecordFailure`.
  Optional interface `FailoverProbeReporter { TryBeginFailoverProbe(cluster) bool; RecordFailoverProbeSuccess(cluster); RecordFailoverProbeFailure(cluster) }`, implemented by both breakers.
  `TryBeginFailoverProbe` is the single-flight open-to-half-open transition:
  under the per-cluster mutex, when the breaker is open, `resetTimeout > 0`, the timeout has elapsed since the last failure, and no probe is in flight, it enters half-open, publishes gauge state 1 through the existing report sequence, and returns true;
  `resetTimeout == 0` never probes (the breaker stays open until `RecordSuccess`, as documented today).
  `RecordFailoverProbeSuccess` is the only close from half-open: event `circuit_breaker_closed` with the new reason `"probe succeeded"`, gauge 0.
  `RecordFailoverProbeFailure` returns to open, restarts the timeout, keeps the trip count, and emits no new open event.
  The `"reset timeout elapsed"` close reason disappears; `docs/cluster-events.md` records both changes.
- The recovery-probe loop drives both authorities.
  On each cluster tick it snapshots demand from the write strategy (`ProbeReporter.IsDegraded` and not latched) and from the failover policy (`TryBeginFailoverProbe`), runs at most one probe when either asked, and reports the outcome only to the authorities captured for that attempt.
  The loop starts when either authority implements its probe interface; `WithRecoveryProbeDisabled()` and single-cluster mode keep their current short-circuits, and a breaker that never gets probed stays open until `RecordSuccess`.

Verification: unskip `TestRead_CircuitBreakerBelowThresholdRetriesOnHealthyCluster`;
breaker tests for open → half-open → success and open → half-open → failure under concurrent `RecordFailure`, asserting event order, reason, gauge, and trip count;
no caller read produces a timeout close once policy probing exists;
cases for `resetTimeout == 0`, probe disabled, single-cluster mode, session swap before a due probe, and `Close` during a probe;
a custom value configured in both probe roles receives one write credit and one breaker outcome from one physical probe;
warning cardinality for both breakers, custom policies, explicit false, explicit true, and the Safe profile.

### 4.8 Read-strategy fixes

- `StickyRead.OnFailure` swaps during cooldown when the failing cluster is the current preferred;
  `Reset()` and `SetPreferred(cluster)` added.
- `PrimaryOnlyRead.Select` single-flights the recovery probe with a compare-and-swap flag
  cleared by `OnSuccess`/`OnFailure`.

Both are Category 1 (documented intent is "avoid oscillation", not "pin to a dead cluster").

Verification: policy tests for the cooldown swap and for concurrent `Select` calls returning one probe.

### 4.9 Replay execution gate

`replay.WithClusterGate(func(cluster types.ClusterID) bool)` on both worker backends answers "may this cluster execute now".
The gate is checked immediately before every execution attempt, not only before dequeue or fetch:
the memory first attempt, every memory retry (bounded and retained), and every message of a fetched NATS batch.
A gated memory payload is parked for one `PollInterval` without consuming an attempt, the retry window, or its retained capacity slot.
A gated NATS message is redelivered with `NakWithDelay(RetryDelay)`;
under `RetryWhileRetained` (the default) deliveries are unlimited, and the docs state that under `RetryBounded` a gated redelivery does count as a delivery.
Dequeue and fetch also consult the gate so queued work stays queued or server-side while gated.
Reopening is observed within `PollInterval`; every gate wait selects on `stopCh` so `Worker.Stop` cannot hang.
The predicate must be non-blocking and concurrent; a panic inside it counts as gated.

Root composes its gate from drain and the operator quarantine predicate of `WithReplayGate(func(ClusterID) bool)` (see Decisions),
and injects it only into the primary worker it builds for `WithAutoMemoryWorker`.
Mirror workers are never gated by the source client: their payloads name a logical sink, not a root cluster; a mirror owner passes its own gate through `NewMirrorWorker` options.
A user-supplied `WithReplayWorker` gets a once-per-client `Warn` that root could not apply or verify replay gating.

Verification: memory tests close the gate after a first retained failure and before its retry is due and prove no second executor call until reopen;
NATS tests close the gate after a multi-message fetch and prove the unprocessed tail is neither executed nor budgeted away;
both backends stop while gated and shut down promptly with the documented retention behaviour;
a root test toggles drain through a topology update and a quarantine predicate;
a mirror test drains source A while mirror retries are queued and proves the mirror worker continues.

### 4.10 Backlog-aware allowed-clusters helper

`helix.ExcludeWhileReplayBacklog(depth func(ClusterID) int, threshold int) AllowedClustersFunc`
excludes a cluster while its pending count exceeds the threshold.
`MemoryReplayer.PendingByCluster` already provides the depth;
the NATS replayer gains an equivalent from consumer info.

Verification: a root test routes reads away from A while its backlog is above the threshold
and back once it drains.

### 4.12 Diagnostics

- Probe failures logged at `Warn` on the first failure and on power-of-two counts, `Debug` otherwise.
- `topology/nats` retries `Watch` on each poll tick after falling back to polling.

## Decisions (2026-09-03)

1. Phase 4 is one PR on `feat/authorities`, one commit per item;
   Phase 5 follows in a second PR and `v1.8.0` is tagged after both merge.
   The roadmap "one PR per numbered item" convention is corrected to match.
2. The replay gate in 4.9 is driven by drain and by an operator quarantine predicate supplied through `WithReplayGate(func(ClusterID) bool)`;
   no mutable quarantine state is added to the client.
3. `WithBehaviorProfile(Safe)` lands after 4.7 as its own commit.
   It sets the root-owned Category 3 knob (route veto on);
   the policy-owned `WithFailoverBelowThreshold` and the replayer-owned stream knobs stay where they are,
   and root's startup `Warn` names the option to change for each one it can observe.
   The roadmap sentence "pure option expansion over the Category 3 knobs" is corrected to say so.
4. The auto-refresh classifier default counts `types.ErrClusterUnreachable` and Helix-owned leg or probe timeouts;
   existing auto-refresh tests move onto the typed sentinel.
5. The hub only aggregates observations;
   write outcomes are not forwarded to the failover policy.
6. Minimum degraded dwell and re-degrade backoff default to zero;
   only the probe latency criterion changes behaviour by default.
7. `WithClusterWriteTimeout` applies to the normal and strict write legs, not to mirror writes.
8. Breaker half-open recovery reuses the recovery-probe loop and `RecoveryProbe` settings.
   The loop starts when the write strategy or the failover policy implements its probe interface;
   `WithRecoveryProbeDisabled()` disables both.
   The failover interface is `FailoverProbeReporter { TryBeginFailoverProbe; RecordFailoverProbeSuccess; RecordFailoverProbeFailure }`,
   named apart from the write-side `ProbeReporter` so one value may implement both without a double credit.
   A successful probe closes the breaker with the new close reason `"probe succeeded"`;
   the timed close inside `RecordFailure` and its `"reset timeout elapsed"` reason are removed.
9. The backlog helper takes `func(ClusterID) int`;
   the docs show how to wrap `MemoryReplayer.PendingByCluster` and a sampled `NATSReplayer.PendingByCluster`.
10. The replaced session in 4.3 closes after `AutoRefresh.RefreshTimeout`;
    `Close()` closes every pending old session immediately and joins that goroutine.
11. Before coding, an external plan review covers the interfaces of 4.2, 4.6, 4.7, and 4.9.
    The first pass (`tmp/v1.8.0-authorities_phase4_interfaces_review.md`) found none of the four ready;
    its findings are folded into the item texts above.
