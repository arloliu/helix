# v1.8.0 Phase 4 — Authorities, per-cluster replay, auto-recovery

Working plan for the Phase 4 items in
[`roadmap.md`](roadmap.md#phase-4--authorities-per-cluster-replay-auto-recovery-v180).
The roadmap table and the Design Decisions section are binding;
this file only fixes the order, the mechanism, and the verification for each item.
Finding IDs stay in the roadmap;
nothing below is quoted into code or commits.

## Scope and process

- Branch `feat/authorities` from `main` (`v1.7.0`, `8d7bdfb`).
  One commit per roadmap item, in the order below;
  two items share a commit only when they touch the same lines.
- Phase 5 (observability) is a second branch and PR after this one merges;
  `v1.8.0` is tagged after both.
- Every item: unskip or write the regression test first, then make it pass.
  Before each commit: `go fix ./...`, `make lint`, `make test-unit`, `/simplify`.
  Run `go test ./test/integration/` before every push that changes behaviour.
- `CHANGELOG.md` `[Unreleased]` gains one entry per observable change,
  with the one-line restore for every default that moves.
- External review (Codex, root-client and policy/replay reviewers in parallel) before the PR is opened,
  looping until both report nothing.

## Items

### 4.1 Per-cluster memory queues

`MemoryReplayer` keeps two channels per cluster (high and low) instead of two shared ones.
`Enqueue` routes by `TargetCluster` and priority;
the per-cluster slot accounting already present (`pendingA`, `pendingB`) stays the capacity authority.
`tryDequeueWithPriority` gains a cluster argument;
the worker's dequeue loop alternates clusters so one cluster's backlog cannot starve the other.
`Len`, `HighLen`, `LowLen`, `PendingByCluster`, and `DrainAll` keep their meaning.
Not observable from the public API except through fairness;
no CHANGELOG entry beyond a note.

Verification: existing replay tests unchanged;
a new test enqueues a backlog for A and confirms B payloads are dequeued while A's remain.

### 4.2 Observation hub

An unexported `clusterHealth` in root owns `clusterStats` and receives every health observation through one method,
`observe(cluster, source, err, latencyNanos)`.
`source` is one of read, write, deferred write, probe, iter close.
Callers: `recordOpOutcomeAt`, `recordWriteOutcomeAt`, `recordReadFailure`/`recordReadSuccess`, `cqlIter.Close`,
`recoveryProbeLoop`, and the deferred-write callback in `replayLeg`.
The hub forwards to the existing authorities exactly as today
(failover policy, read strategy, latency recorder, auto-refresh stats);
it adds no translation between them.
No exported API changes.

Verification: the read matrix test and the write regression tests are unchanged;
a hub unit test pins which sources reach which authority.

### 4.3 Auto-refresh consumes hub observations

- Seed `lastSuccessNanos` at construction and on every session swap.
- Deferred-write failures and recovery-probe failures reach the auto-refresh counters through the hub
  (source deferred write and probe).
- `WithAutoRefreshFailureClassifier(func(error) bool)`;
  the default counts `types.ErrClusterUnreachable` and Helix-owned leg or probe timeouts.
  Restore the old behaviour with `WithAutoRefreshFailureClassifier(func(error) bool { return true })`.
- `RefreshSession` closes the replaced session after a grace period (default one refresh timeout)
  instead of immediately, so in-flight operations on the old holder finish.

Category 1 for the first two bullets (documented "ALL of" contract);
CHANGELOG behaviour change for the classifier default.

Verification: unskip `TestAutoRefresh_DegradedClusterFailuresStillTriggerRefresh`
and `TestAutoRefresh_DoesNotReplaceHealthySessionOnSchemaErrors`;
the existing auto-refresh tests move their simulated errors onto the typed sentinel.

### 4.4 `ForceDegrade` sticky latch

`clusterWriteState` gains a `latched` flag set by `ForceDegrade`, cleared only by `ForceRecover` and `Reset`.
`recordFast` and `RecordProbeSuccess` never clear `isDegraded` while latched.
`recoveryProbeLoop` skips a latched cluster through a new optional interface (`IsLatched`),
so custom strategies are unaffected.
`docs/auto-recovery.md` documents the latch and drops the advice to disable the probe.
Category 1;
CHANGELOG behaviour change with no restore (no dependent identified).

Verification: unskip `TestRecoveryProbe_DoesNotClearForceDegrade`.

### 4.5 Probe hysteresis

- The probe credits recovery only when its own latency is within the strategy's `absoluteMax`
  (or the sibling's last latency plus the delta threshold).
  `RecordProbeSuccess` gains a sibling `RecordProbeLatency(cluster, d)` on a new optional interface;
  the old method is kept.
- `WithAdaptiveMinDegradedDwell(d)`: no recovery before `d` has elapsed since the degrade.
- Re-degrade backoff: each degrade within a window doubles the dwell, capped;
  a new `EventWriteFlapping` fires when the cap is reached.

Defaults keep today's behaviour (zero dwell, no backoff), so the dwell and backoff are additive.
The latency criterion is Category 1 because the documented probe contract is "the cluster responded quickly".

Verification: a policy test with a fast probe and slow writes stays degraded;
a flapping test counts transitions and the event.

### 4.11 `WithClusterWriteTimeout`

Root wraps each leg context in `writeLegs` with the configured timeout.
Expiry is a Helix-owned timeout:
`classifyWriteLeg` already treats a leg error with a live parent as a cluster error,
so the leg is replayed and counted as a health signal without new classification code.
Default zero (disabled).

Verification: a write test with one hanging session returns after the timeout,
acknowledges the fast leg, and enqueues replay for the slow one.

### 4.6 Route veto

Optional interface in root: `RouteVeto { VetoRoute(cluster ClusterID) bool }`.
`resolveReadTargetNormal` consults it after `Select`;
a vetoed cluster is replaced by the alternative for that request only, never calling `OnFailure`.
`LatencyCircuitBreaker` implements it (open breaker vetoes).
Category 3: off by default;
`WithRouteVeto(true)` enables it;
a startup `Warn` when the failover policy implements the interface and the option is off.
`docs/cluster-events.md` corrects the `circuit_breaker_open` action text.

Verification: unskip `TestRead_OpenLatencyBreakerReroutesReads` with the option enabled.

### 4.7 Breaker below threshold and policy probe

- `WithFailoverBelowThreshold(bool)` on `NewCircuitBreaker` (default `false`, Category 3, startup `Warn` when off).
- Half-open recovery moves to root.
  An optional `FailoverProbeReporter { NeedsProbe(cluster) bool; RecordProbeSuccess(cluster); RecordProbeFailure(cluster) }`
  is implemented by both breakers.
  The existing recovery-probe loop drives it with the same `RecoveryProbe` configuration,
  so the half-open request no longer costs a caller's read.
- `ShouldFailover` evaluates the reset timeout lazily,
  so the state gauge cannot stay open once the timeout has elapsed.

Verification: unskip `TestRead_CircuitBreakerBelowThresholdRetriesOnHealthyCluster`;
a probe test closes an open breaker without any caller read.

### 4.8 Read-strategy fixes

- `StickyRead.OnFailure` swaps during cooldown when the failing cluster is the current preferred;
  `Reset()` and `SetPreferred(cluster)` added.
- `PrimaryOnlyRead.Select` single-flights the recovery probe with a compare-and-swap flag
  cleared by `OnSuccess`/`OnFailure`.

Both are Category 1 (documented intent is "avoid oscillation", not "pin to a dead cluster").

Verification: policy tests for the cooldown swap and for concurrent `Select` calls returning one probe.

### 4.9 Replay execution gate

`replay.WithClusterGate(func(cluster types.ClusterID) bool)` on both worker backends:
a gated cluster's queue is not dequeued (memory) or its consumer is not fetched (NATS) until the gate opens.
Root injects a gate that returns false while the cluster is draining,
for the workers it builds (`WithAutoMemoryWorker`, `WithMirrorReplayer`).
A user-supplied `WithReplayWorker` gets a startup `Warn` that drain gating is not applied.
Operator quarantine has no existing API;
see open question 3.

Verification: a worker test with a gated cluster leaves its payloads queued and drains them once the gate opens;
a root test toggles drain through a topology update.

### 4.10 Backlog-aware allowed-clusters helper

`helix.ExcludeWhileReplayBacklog(depth func(ClusterID) int, threshold int) AllowedClustersFunc`
excludes a cluster while its pending count exceeds the threshold.
`MemoryReplayer.PendingByCluster` already provides the depth;
the NATS replayer gains an equivalent from consumer info.

Verification: a root test routes reads away from A while its backlog is above the threshold
and back once it drains.

### 4.12 Diagnostics

- Probe failures logged at `Warn` on the first failure and on power-of-two counts, `Debug` otherwise.
- `topology/nats` retries `Watch` on each poll tick after falling back to polling.

## Decisions (2026-09-03)

1. Phase 4 is one PR on `feat/authorities`, one commit per item;
   Phase 5 follows in a second PR and `v1.8.0` is tagged after both merge.
   The roadmap "one PR per numbered item" convention is corrected to match.
2. The replay gate in 4.9 is driven by drain only;
   operator quarantine has no API in this release.
3. `WithBehaviorProfile(Safe)` lands after 4.7 as its own commit.
   It sets only root-owned knobs (route veto on);
   the startup `Warn` for a legacy breaker or replayer names the option to change.
4. The auto-refresh classifier default counts `types.ErrClusterUnreachable` and Helix-owned leg or probe timeouts;
   existing auto-refresh tests move onto the typed sentinel.
5. The hub only aggregates observations;
   write outcomes are not forwarded to the failover policy.
6. Minimum degraded dwell and re-degrade backoff default to zero;
   only the probe latency criterion changes behaviour by default.
7. `WithClusterWriteTimeout` applies to the normal and strict write legs, not to mirror writes.
8. Breaker half-open recovery reuses the recovery-probe loop and `RecoveryProbe` settings.
   The loop starts when the write strategy or the failover policy implements its probe interface;
   `WithRecoveryProbeDisabled()` disables both.
   `FailoverProbeReporter { NeedsProbe(cluster) bool; RecordProbeSuccess(cluster); RecordProbeFailure(cluster) }`
   is implemented by both breakers.
   `NeedsProbe` is true while the breaker is open and `resetTimeout` has elapsed since the last failure;
   a zero `resetTimeout` never probes.
   A successful probe closes the breaker with the new close reason `"probe succeeded"`,
   documented in `docs/cluster-events.md`.
9. The backlog helper takes `func(ClusterID) int`;
   the docs show how to wrap `MemoryReplayer.PendingByCluster` and a sampled `NATSReplayer.PendingByCluster`.
10. The replaced session in 4.3 closes after `AutoRefresh.RefreshTimeout`;
    `Close()` closes every pending old session immediately and joins that goroutine.
11. Before coding, an external plan review covers the interfaces of 4.2, 4.6, 4.7, and 4.9.
