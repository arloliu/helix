# Plan: `Strict()` Per-Statement Option for Strong-Consistency CQL Writes

> **Revision 5** — makes `Strict().Mirror()` unsupported. `Strict()` is primarily for replay-unsafe writes, and the mirror destination may have its own replay path; rather than guessing which CQL statements are safe, Helix rejects the combination. Also keeps the recovery probe default-on with a lightweight read probe; write probes are optional, not the default design.
>
> **Revision 4** — previously proposed dispatching `Strict().Mirror()` on partial success; superseded by Revision 5.
>
> **Revision 3** — incorporates review findings from `tmp/v1.4.0-strict-write-review.md` and adds probe-based auto-recovery (`AdaptiveDualWrite`) so strict-only workloads do not strand a degraded cluster, preserving Helix's auto-healing principle.

## Context

Helix's current dual-write path **always** treats partial failure as silent success and enqueues the failed cluster's write into the replayer (or fire-forgets it under `AdaptiveDualWrite`, or skips-and-enqueues under drain mode at `cql_client.go:439`). This is correct for the common case because client-generated timestamps make a replayed write idempotent under Cassandra LWW (verified at `cql_client.go:1502` + `1987-2028` + comment at `1467-1468`). But it breaks down for three classes of writes:

1. **Counters** — replay double-counts (docs already warn about this).
2. **List/set append/prepend** — replay duplicates elements.
3. **Tombstone-resurrection window** — a delayed replay arriving after `gc_grace_seconds` can resurrect a deleted row.

These callers need **synchronous, ack-or-uncertainty semantics**: either the write is acknowledged on both clusters, or the caller is told *one cluster did not ack* (timeout, error, degraded, draining) and decides whether to retry, compensate, or accept the divergence.

### What the guarantee is — and is not

`Strict()` provides:

- **No Helix-side replay** of a partial-failure write — eliminates double-apply on retry queues.
- **No fire-and-forget** dispatch under `AdaptiveDualWrite` — never silently swallows a write.
- **Explicit caller-visible partial-failure surface** — `*PartialWriteError` names the unacknowledged cluster.
- **Auto-recovery preserved**: a probe loop continues to test degraded clusters in the background even when all writes are strict, so degraded state is not permanent.

`Strict()` does **NOT** provide:

- **Atomicity across clusters.** A `PartialWriteError` means "the unacknowledged cluster did not respond OK before the deadline." It does NOT prove the mutation was not applied — it may have committed and the response was lost. Caller compensations and retries on `PartialWriteError` can still double-apply for non-idempotent ops; this is a fundamental Cassandra/network property, not a Helix guarantee gap.
- **Exactly-once writes.** Helix cannot, and does not claim to, deliver exactly-once across two independent clusters.
- **Divergence detection.** If both clusters have the row but at different timestamps/values, `Strict()` does not detect that — neither at write time nor at read time. (See FallbackRead notes below.)

### Shared-nothing principle preserved

A degraded cluster must **not** block service. `Strict()` therefore *fast-fails* on a known-degraded or draining cluster — it never waits — and returns control to the caller. The healthy cluster still gets the write at normal latency.

The user-facing example (status field flip PENDING→COMPLETED) is **already protected** by automatic timestamps and does not need this feature; the Godoc explicitly directs callers away from `Strict()` for that case.

## Design Summary

`Strict()` is a per-statement opt-in on `Query` and `Batch`, parallel to existing `Mirror()` / `FallbackRead()`. When set:

| Scenario                                      | Behavior                                                                      |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| Both clusters ack                             | Return `nil`                                                                  |
| One cluster fails / times out                 | Return `*types.PartialWriteError{Acknowledged, Unacknowledged, Cause}`; **no replay** |
| One cluster known-degraded (Adaptive)         | **Skip the write** to that cluster; return `*PartialWriteError` with `Cause = ErrClusterDegraded`; **no replay**; **probe loop continues to drive recovery** |
| One cluster draining (topology)               | **Skip the write** to that cluster; return `*PartialWriteError` with `Cause = ErrClusterDraining`; **no replay** |
| Both clusters fail / degraded / draining      | Return `*types.DualClusterError`; **no replay**                               |
| Cluster slow but not flagged                  | Bounded by caller's context deadline; on timeout → `*PartialWriteError`       |
| `Strict().Mirror()`                           | Return `ErrStrictMirrorUnsupported` before attempting the write; **no write**, **no mirror**, **no replay** |
| Single-cluster mode                           | `Strict()` is a no-op (single write returns its error directly); documented   |
| CAS / LWT (`ScanCAS`, `ExecCAS`, etc.)        | `Strict()` is a no-op (already single-cluster per `cql_client.go:1066-1069`); documented |

## Public API Changes

### 1. `Query` and `Batch` interfaces (`cql_session.go`)

Add `Strict() Query` and `Strict() Batch`, mirroring the shape of `Mirror()` at lines 141 and 376.

```go
// Strict marks the statement for strong-consistency dual-write semantics.
//
// On partial failure (one cluster fails, times out, is degraded, or is
// draining), Strict returns *types.PartialWriteError instead of silently
// enqueueing for replay. On AdaptiveDualWrite, Strict fast-fails to
// degraded clusters rather than fire-and-forgetting; the recovery
// probe continues running in the background so degraded clusters
// still self-heal. Pair with FallbackRead() on reads when the row may
// be absent on one cluster.
//
// What Strict guarantees: no Helix-side replay; no fire-and-forget;
// explicit partial-failure surface to the caller.
//
// What Strict does NOT guarantee: atomic dual-cluster writes,
// exactly-once delivery, or divergence detection. A PartialWriteError
// means the unacknowledged cluster did not respond OK before the
// deadline; the mutation MAY have applied. Caller retries on
// PartialWriteError can still double-apply non-idempotent ops.
//
// Use only for writes whose replay is unsafe (counters, list/set
// append, tombstone-race-sensitive flows). Normal column overwrites
// are already replay-safe via timestamps; using Strict() for those
// is unnecessary.
//
// Strict and Mirror are mutually exclusive in v1.4.0. Strict is
// intended for replay-unsafe writes, while Mirror may dispatch into
// another dual-cluster Helix target with its own replay behavior.
// Because Helix does not parse CQL deeply enough to prove whether a
// statement is replay-safe, Strict().Mirror() fails fast with
// ErrStrictMirrorUnsupported before attempting the write.
func (q Query) Strict() Query
func (b Batch) Strict() Batch
```

### 2. `types.PartialWriteError` (`types/types.go`, near `DualClusterError` at 319-361)

```go
// PartialWriteError indicates that a Strict() write was acknowledged
// by exactly one cluster. The other cluster did not respond OK before
// the deadline; the mutation MAY OR MAY NOT have applied there.
//
// Callers MUST NOT assume the unacknowledged cluster is in a known
// state. Compensating retries on non-idempotent operations
// (counters, list/set append) can double-apply.
type PartialWriteError struct {
    Acknowledged   ClusterID  // cluster that returned OK
    Unacknowledged ClusterID  // cluster that did not ack (cause in Cause)
    Cause          error      // underlying cause: timeout, sentinel, or driver error
}

func (e *PartialWriteError) Error() string {
    return fmt.Sprintf("helix: strict write acknowledged on %s but not on %s: %v",
        e.Acknowledged, e.Unacknowledged, e.Cause)
}

func (e *PartialWriteError) Unwrap() error { return e.Cause }
```

### 3. New sentinel errors (`types/types.go`)

```go
// ErrClusterDegraded indicates a Strict() write was skipped because
// the cluster is currently flagged degraded by AdaptiveDualWrite.
ErrClusterDegraded = errors.New("helix: cluster is degraded; strict write skipped")

// ErrClusterDraining indicates a Strict() write was skipped because
// the cluster is currently in topology drain mode.
ErrClusterDraining = errors.New("helix: cluster is draining; strict write skipped")

// ErrStrictUnsupported indicates the configured WriteStrategy does
// not implement StrictWriter and a Strict() statement was attempted.
ErrStrictUnsupported = errors.New("helix: configured WriteStrategy does not support Strict() writes")

// ErrStrictMirrorUnsupported indicates Strict() and Mirror() were
// combined on one statement. Helix rejects this before attempting
// the write because strict writes are commonly replay-unsafe, and
// mirror destinations may retry or replay failed mirror dispatches.
ErrStrictMirrorUnsupported = errors.New("helix: Strict() and Mirror() cannot be combined")
```

### 5. Recovery probe (NEW — addresses auto-healing for strict-only workloads)

`RecoveryProbe` lives in the root `helix` package, not `types`, because its `Probe` function accepts `adapter/cql.Session`. The `types` package must remain a leaf package and cannot import the adapter layer.

```go
// RecoveryProbe configures background health probes for clusters
// that AdaptiveDualWrite has marked degraded. The probe runs only
// while a cluster is degraded; successful probes feed the existing
// recovery counter and eventually restore the cluster to healthy.
//
// Probes ensure strict-only workloads (which skip degraded clusters
// entirely and produce no native write-side recovery signal) still
// benefit from Helix's auto-healing principle.
type RecoveryProbe struct {
    // Probe is the function called periodically to test cluster
    // liveness while degraded. Returning nil credits one recovery
    // tick; non-nil error is logged and the cluster stays degraded.
    //
    // Default: a lightweight read of system.local that exercises
    // the driver and connection path without writing data:
    //
    //   func(ctx, s) error {
    //       return s.Query("SELECT release_version FROM system.local").
    //           IterContext(ctx).Close()
    //   }
    //
    // The default is intentionally read-only: in normal operations,
    // a restarted Cassandra/Scylla cluster that can answer this query
    // is overwhelmingly likely to accept writes again. If a deployment
    // has known write-path-only failure modes, operators MAY override
    // the probe with a write-path check against a dedicated probe table.
    Probe func(ctx context.Context, session cql.Session) error

    // Interval between probe attempts. Default: 2s.
    Interval time.Duration

    // Timeout per probe attempt. Default: 1s. Must be < Interval.
    Timeout time.Duration
}
```

**Client option** (root helix package):

```go
// WithRecoveryProbe configures the recovery probe for AdaptiveDualWrite.
// Has no effect when the WriteStrategy is not *AdaptiveDualWrite.
// Default: enabled with the default probe; pass an empty Probe to
// retain defaults, or use WithRecoveryProbeDisabled to opt out.
func WithRecoveryProbe(p RecoveryProbe) Option

// WithRecoveryProbeDisabled disables the recovery probe entirely.
// Operators choosing this MUST use ForceRecover or non-strict
// writes to recover degraded clusters.
func WithRecoveryProbeDisabled() Option
```

**AdaptiveDualWrite additions**:

```go
// RecordProbeSuccess credits one successful recovery probe against
// the cluster. After the existing consecutive-fast threshold is
// reached, the cluster transitions back to healthy. Safe to call
// when the cluster is not degraded (no-op).
func (a *AdaptiveDualWrite) RecordProbeSuccess(cluster types.ClusterID)
```

This wraps the existing private `recordFast` so probes feed the same recovery counter as natural fast writes — no duplication of recovery logic.

## Implementation

### 1. Statement plumbing

- **`cql_session.go`** — add `Strict() Query` / `Strict() Batch` to interfaces.
- **`cql_client.go`**
  - `cqlQuery` (~1888) and `cqlBatch` (~2154): add `strict bool` field.
  - Implement `Strict()` next to `Mirror()` (1939 / 2202).
  - `writeContext`: add `strict bool`.
  - `ExecContext` paths propagate the flag.
    - **Mirror interaction**: add a preflight guard in query and batch `ExecContext`: if `strict && mirror`, return `types.ErrStrictMirrorUnsupported` before executing the write. Do not dispatch mirror, do not enqueue replay, and do not mutate either cluster.

### 2. Drain path (review #1)

`cql_client.go::executeWriteWithDrain` accepts the `strict` flag via `writeContext`:

- **One draining + strict + healthy side acks**: write only the healthy cluster; do NOT enqueue replay; return `*PartialWriteError{Cause: ErrClusterDraining}`.
- **One draining + strict + healthy side fails**: do NOT enqueue replay; return `*DualClusterError` containing the healthy-side error and `ErrClusterDraining` for the skipped side. No mirror dispatch.
- **Both draining + strict**: do NOT enqueue replay; return `*DualClusterError{ErrorA: ErrClusterDraining, ErrorB: ErrClusterDraining}`.
- Non-strict drain behavior unchanged.

### 3. Strategy contract (review #4)

Define `StrictWriter`; **all built-ins implement it**:

```go
// policy/write_strategy.go
type StrictWriter interface {
    WriteStrategy
    ExecuteStrict(ctx context.Context, writeA, writeB func(context.Context) error) (errA, errB error)
}
```

| Strategy              | `ExecuteStrict` behavior                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `ConcurrentDualWrite` | Identical to `Execute` (already synchronous, no fire-forget). Trivial wrapper.                                           |
| `SyncDualWrite`       | Identical to `Execute`. Caller's ctx-cancel between first and second write surfaces as `*PartialWriteError`.             |
| `AdaptiveDualWrite`   | For each cluster: if `IsDegraded(c)`, return `ErrClusterDegraded` for that cluster *without invoking writeFunc*. Otherwise run writeFunc concurrently with no fire-forget conversion. If the non-degraded side also fails, the orchestrator returns `*DualClusterError` because neither cluster acknowledged. |

Custom strategies that do NOT implement `StrictWriter`: orchestrator returns `ErrStrictUnsupported` immediately, without attempting the write.

If `WriteStrategy` is nil, strict writes use the same built-in default as non-strict writes: concurrent dual-write to both clusters. Nil strategy is not treated as unsupported.

### 4. Orchestrator (`executeDualWrite`)

```
if wc.strict:
    if strategy == nil:
        errA, errB = defaultConcurrentStrict(ctx, writeA, writeB)
        goto surfaceStrictResult
    if !strategy.implements(StrictWriter):
        return ErrStrictUnsupported
    errA, errB = strategy.ExecuteStrict(ctx, writeA, writeB)
    [skip enqueueReplayIfNeeded entirely]
surfaceStrictResult:
    surface result:
        both nil          -> nil
        both non-nil      -> *DualClusterError{ErrorA, ErrorB}
        only errA non-nil -> *PartialWriteError{Acknowledged: B, Unacknowledged: A, Cause: errA}
        only errB non-nil -> *PartialWriteError{Acknowledged: A, Unacknowledged: B, Cause: errB}
else:

```

### 5. Health/metrics signal classification (review #9)

Skipped-due-to-degraded / skipped-due-to-draining writes are operational state, not failures:

- **`recordOpOutcomeAt`**: extend skip list with `ErrClusterDegraded`, `ErrClusterDraining`. They must NOT count as failures.
- **Metrics**: add `IncWriteSkipped(cluster)` (parallel to `IncWriteAsync`/`IncWriteDropped`). Do NOT increment `IncWriteError`.
- **Logger**: info-level (not warn) when a strict write is skipped due to known degraded/draining.

### 6. Recovery probe (NEW)

**Goroutine ownership**: `CQLClient` runs the probe (it has session access). Two goroutines, one per cluster, started at client init when `WriteStrategy.(*AdaptiveDualWrite)` is detected and probe is enabled.

Implementation adds a small recovery-probe lifecycle to `CQLClient` (for example `recoveryProbeCtx`, `recoveryProbeClose`, and a `sync.WaitGroup`). `Close()` cancels the probe context before closing sessions and waits for probe goroutines to exit, so a probe cannot race indefinitely against session close.

```go
// cql_client.go (or new cql_client_recovery.go)

func (c *CQLClient) startRecoveryProbes() {
    a, ok := c.config.WriteStrategy.(*policy.AdaptiveDualWrite)
    if !ok || c.config.RecoveryProbe == nil {
        return
    }
    for _, cluster := range []ClusterID{ClusterA, ClusterB} {
        c.recoveryProbeWG.Go(func() { c.recoveryProbeLoop(cluster, a) })
    }
}

func (c *CQLClient) recoveryProbeLoop(cluster ClusterID, a *policy.AdaptiveDualWrite) {
    p := c.config.RecoveryProbe
    ticker := time.NewTicker(p.Interval)
    defer ticker.Stop()
    for {
        select {
        case <-c.recoveryProbeCtx.Done():
            return
        case <-ticker.C:
            if !a.IsDegraded(cluster) {
                continue // healthy; nothing to do
            }
            ctx, cancel := context.WithTimeout(c.recoveryProbeCtx, p.Timeout)
            session := c.getSession(cluster)
            err := p.Probe(ctx, session)
            cancel()
            if err == nil {
                a.RecordProbeSuccess(cluster)
                c.config.Metrics.IncRecoveryProbeSuccess(cluster)
            } else {
                c.config.Metrics.IncRecoveryProbeFailure(cluster)
                c.config.Logger.Debug("recovery probe failed",
                    "cluster", c.clusterName(cluster), "error", err)
            }
        }
    }
}
```

**Lifecycle**:

- Started at `NewCQLClient` when AdaptiveDualWrite + probe enabled.
- Stopped at `Close()` via `recoveryProbeCtx` cancellation; `Close()` waits for probe goroutines before closing sessions.
- Idle (no probe call) when cluster is healthy — only ticker fires.
- Active during degraded state, advancing recovery counter on each successful probe until cluster recovers.
- Recovery threshold reuses the existing `AdaptiveDualWrite.recoveryThreshold` setting; no new tunable.

**Probe-write-vs-read trade-off** (documented):

The default probe is a lightweight read of `system.local`. This is intentional: it proves the driver/connection path without creating probe rows, schema requirements, or write traffic. In the normal case, once a restarted Cassandra/Scylla cluster can answer this read, it can also accept writes. If the cluster still has a write-path-only problem, the next strict write will fail visibly and adaptive health can mark it degraded again.

Operators with known write-path-only failure modes MAY configure a custom write-path probe against a dedicated probe table, but v1.4.0 does not make write probes the default.

**Failure mode**: if the probe itself is broken (configuration error, schema missing), it logs at debug and never advances recovery — caller still has `ForceRecover` as escape valve. Probe failures do NOT degrade a healthy cluster (probes are recovery-only signals).

## Compatibility Impact

**Source-breaking** for any user that:

- Implements `helix.Query`, `helix.Batch`, or `helix.CQLSession` (e.g., custom mocks, decorators, alternate session impls).
- Implements `types.MetricsCollector`, if the new strict/probe metrics are added to the core interface. If we want to avoid this extra break, make probe metrics an optional interface following the existing `SessionRefreshMetrics` / `MirrorMetrics` pattern.

**Migration**: switch to embedding the helix interface in mock types so new methods are picked up automatically:

```go
type myMockQuery struct {
    helix.Query   // embed
    // overrides...
}
```

Helix's own internal mocks must be updated as part of this PR.

Probe is **default-on** for `AdaptiveDualWrite` users — operationally additive, not source-breaking. Operators who specifically want fully manual recovery use `WithRecoveryProbeDisabled()`.

Release as part of **v1.4.0** (alongside async-mirror). Document in CHANGELOG and release notes.

## Out of Scope (deferred)

- A global "strict mode" client option (`WithStrictWrites(true)`).
- Active read repair / divergence detection — `FallbackRead` covers absence; divergence is a known gap that mirrors today's replay-window behavior.
- Strict semantics on CAS/LWT — already single-cluster; not applicable.
- Distributed atomicity / exactly-once delivery — outside Helix's scope.
- Per-cluster probe configuration (different probes for ClusterA vs ClusterB) — single probe config applies to both; users with asymmetric needs can switch to manual `ForceRecover`.
